# Architecture: why continuous-time, first-order, return-to-zero

**The chip is one modulator producing one bitstream that is decimated two
ways at once** by whatever receives it — the reference setup is an FPGA
(e.g. a PolarFire SoC) that also supplies a clean, low-jitter clock:

| Path | Bandwidth | Target | Use |
|---|---|---|---|
| Fast | ~1 MHz (OSR 25) | ≥ 6–7 effective bits (ENOB) | protection / trip decisions |
| Precision | ~100 kHz (OSR 250) | 10–12 ENOB | measurement |

Every choice below is logged with its rationale (and its *reopen
conditions*) in the repository's append-only
[decision log](https://gitlab.com/pthomas1/sigma-delta/-/blob/main/DESIGN.md);
this chapter is the narrative version.

**Continuous-time, active-RC.** A CT loop's input network is a resistor
into a virtual ground — intrinsically anti-aliasing, no switched-capacitor
front end, no boosted clocks. The loop coefficient k = T<sub>s</sub>/(R·C)
lands at friendly on-chip values (~40 kΩ high-res poly, 1–2 pF MiM cap) at
f<sub>s</sub> = 50 MHz. The costs — sensitivity to the feedback pulse
*shape* and to clock jitter — are exactly the things the architecture then
has to manage, which is what the rest of this page is about.

**First order, 1 bit.** One integrator, one comparator, both reused
unchanged by a future second-order upgrade. The performance budget
(measured, not just the textbook formula): the linear model promises
74.5 dB SQNR at OSR 250, but a first-order loop's in-band error is
**pattern tones, not white noise**<sup>[[1]](#references)</sup> — long-run tier-0 simulation converges
to ~66 dB signal-to-noise-and-distortion ratio (SNDR), and 16k-bit windows scatter over 54–67 dB depending on
dither seed. That measured gap is the strongest argument for the
second-order upgrade if the 12-bit target firms up; it is also why the CI
assertions use loose SNDR floors rather than exact values (a chaotic
modulator's per-window SNDR is not a stable regression quantity).

**Return-to-zero (RZ) feedback DAC — chosen by experiment.** A
single-ended NRZ DAC's dominant error is inter-symbol interference (ISI)<sup>[[2]](#references)</sup>: the
energy a feedback pulse delivers depends on the *previous* bit (rise and
fall edges don't cancel), which demodulates shaped noise back into the
band. An RZ pulse pays its edges every cycle, making the per-bit charge
history-independent — at the price of doubled jitter sensitivity (retired
here by the external clock) and higher peak currents. The four-corner
simulation matrix ({NRZ, RZ} × {edge asymmetry, jitter}) confirmed the
presumption; the comparison report is generated by `make report`
({{report_links}}).

**Excess loop delay is modeled from day one — and it still bit
us.**<sup>[[3]](#references)</sup> The loop budget allocates a full
clock cycle for comparator regeneration + DAC settling; at 50 MHz
that's a first-order effect, not a refinement. The comparator gets a
hard spec from this: full regeneration within its 10 ns half-period,
because a *soft* decision leaks through the DAC as unshaped noise (a
~25 dB SNDR penalty was measured when violated). The subtle half of
the same budget was caught late (2026-07-25): a StrongARM samples its
input the instant its tail activates, so clocked on clk33 it sensed
the integrator half a cycle *earlier* than the tier-0/1 models
assumed — ~4 dB of fast-path SNDR. The shipped loop clocks the
comparator on the complement clock (sensing at the clk33 rise,
exactly the modeled instant) and drives the DAC data switches from
the comparator's own SR latch, which holds all cycle — data settles
~8 ns before the RZ window opens. The retiming DFF stays on the
output pins.

**Area reality check.** A TinyTapeout 1×2 analog tile is 160×225 µm. The
budget puts the full first-order chip at ~18,000 µm² ≈ 50% of one 1×2
tile pair — comfortable; the second-order upgrade would push ~75%, arguing
for a 2×2 purchase if that's the ambition. *(As built: the routed
assembly spreads to ~314 µm width — corridor and clearance rules, not
device area, set the floorplan — so the submitted chip occupies the 2×2
frame.)*

## Pins and the TinyTapeout boundary

The chip uses **two analog pins**, and neither the clock nor the data is
one of them:

| Signal | TT pin | Type |
|---|---|---|
| VIN — analog input, 0–3.3 V about the 1.65 V mid-scale | `ua[0]` | analog |
| INT — integrator output monitor | `ua[1]` | analog (debug only; the ADC runs without it) |
| Clock in, 50 MHz | `clk` | digital, 1.8 V (level-shifted to 3.3 V on-chip) |
| Bitstream Q | `uo[0]` | digital, 1.8 V |
| Bitstream Q̄ | `uo[1]` | digital, 1.8 V |

plus the three supplies (VDPWR 1.8 V, VAPWR 3.3 V, VGND). Analog pins
are scarce on TinyTapeout (six maximum); VIN genuinely needs one, and
the second buys silicon-debug visibility into the integrator.

**Why IO edge asymmetry doesn't threaten this loop.** A fair question
from the community: TinyTapeout's IO paths don't guarantee equal
rise/fall propagation delays, which is a classic hazard for sigma-delta
*DACs* — there, the analog value *is* the pin waveform's time-average,
so duty-cycle distortion is direct signal distortion. This ADC crosses
the TT boundary with three signals, and each is immune for a different
reason:

- **The feedback DAC never leaves the chip.** The only waveform whose
  shape carries analog information is the internal RZ feedback pulse,
  and RZ was chosen (by the four-corner experiment above) precisely so
  that edge errors are pattern-*independent* — a static gain term, not
  distortion. No TT pin is in that path.
- **The clock path's asymmetry is a static duty shift.** RZ pulse width
  is set by the clock phases, so duty distortion changes loop gain — the
  benign error class. The on-chip level shifter was gated at ≤ 3% added
  duty distortion (measured 2.42% worst-case); only edge *noise*
  (jitter) would be an SNDR term, and the clean external clock retires
  it.
- **The bitstream is symbols, not a waveform.** The FPGA captures one
  bit per clock period synchronously and decimates numerically; pin edge
  positions never enter the signal path (the retiming DFF guarantees
  zero mid-cycle transitions, and the Q/Q̄ pair allows differential
  capture). Edge asymmetry would only matter if the output were
  reconstructed analog-style — RC-filtering the pin like a DAC — which
  is not how an ADC's bitstream is used.
